# Словарь данных

## 1. Назначение

Документ описывает основные атрибуты наборов данных, их физический смысл и аналитическую роль в исследовании.

Атрибуты разделяются на:

- характеристики игры;
- показатели интереса аудитории;
- временные характеристики;
- идентификаторы и атрибуты интеграции;
- текстовые характеристики.

Названия полей в таблицах соответствуют используемым в проекте представлениям данных. Фактические типы и наличие полей дополнительно проверяются на этапе профилирования 2.3.

## 10. Steam Reviews

Источник: `raw/steam/reviews/dataset.csv`.

Steam Reviews используется как основной источник пользовательских текстов.

Фактические названия полей фиксируются по результатам профилирования в 2.3. До проверки схемы не предполагается наличие конкретных полей, кроме того, что источник выбран для анализа пользовательских отзывов.

В итоговом словаре после профилирования должны быть описаны:

- идентификатор отзыва;
- идентификатор игры, если присутствует;
- текст отзыва;
- оценка или признак рекомендации, если присутствует;
- временные характеристики, если присутствуют;
- дополнительные числовые и категориальные характеристики, доступные в файле.

При обработке выборки необходимо сохранить связь отзыва с исходной игрой и не смешивать идентификатор отзыва с идентификатором игры.

## 12. Общие атрибуты для интеграции

| Источники | Возможный общий атрибут | Надёжность |
|---|---|---|
| Steam — Steam Monthly Players | `appid` / `steam_appid` | Высокая |
| Steam — RAWG | Нормализованное название, дата выхода | Средняя / низкая |
| Steam — Epic | Нормализованное название, дата выхода | Средняя / низкая |
| Steam — Twitch | Нормализованное название игры | Средняя / низкая |
| Steam — YouTube | Название игры, использованное в поисковом запросе | Средняя / низкая |
| Steam — Wikidata | Нормализованное название, дата выхода, разработчик | Средняя / низкая |

Совпадение названий не гарантирует идентичность игры. Для интеграции между платформами требуется нормализация названий и дополнительная проверка неоднозначных совпадений.

## 13. Принципы обработки пропусков

- Отсутствующие рейтинги не заменяются нулём.
- Отсутствующие даты не восстанавливаются без подтверждённого источника.
- Неизвестные категории сохраняются как пропуски или отдельная категория только при обоснованной необходимости.
- Пропуски в статистике YouTube не интерпретируются как отсутствие просмотров.
- Отсутствующие характеристики Wikidata не заполняются искусственно.
- При расчёте производных показателей учитывается количество доступных наблюдений.
- Для текстовых источников пустые и технические записи обрабатываются отдельно от обычных пропусков.
