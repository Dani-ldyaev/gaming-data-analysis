# Архитектура проекта

## Общая схема

Проект обрабатывает данные последовательно: ноутбук 2.2 получает исходные данные, ноутбук 2.3 преобразует их и формирует аналитическое хранилище. Ноутбуки 2.4–2.6 используют подготовленные результаты для анализа, сравнения методов и представления выводов.

## Логическая структура хранилища

Данные сохраняются в таблицах по источникам и по типу наблюдений. Таблицы с разной детализацией остаются отдельными: например, запись рекомендации, игра за месяц и видеоролик — это разные сущности.

```text
                         ┌───────────────────┐
                         │    steam_games    │
                         │ ключ: AppID       │
                         └───────┬───────────┘
                                 │
                    AppID       │       app_id
              ┌─────────────────┴──────────────────┐
              ▼                                    ▼
┌─────────────────────────┐          ┌──────────────────────────┐
│ steam_monthly_players   │          │ steam_recommendation_games│
│ игра × месяц            │          │ каталог игр рекомендаций │
└─────────────────────────┘          └────────────┬─────────────┘
                                                  │ app_id
                                                  ▼
                                     ┌────────────────────────┐
                                     │ steam_recommendations  │
                                     │ отзыв / рекомендация   │
                                     └────────────────────────┘

┌──────────────┐      ┌──────────────────────┐
│  rawg_games  │      │ wikidata_games       │
│ ключ: id     │      │ ключ сущности: game  │
└──────┬───────┘      └──────────┬───────────┘
       └──────────────┬──────────┘
                      │ кандидаты по нормализованному названию
                      ▼
          ┌─────────────────────────────┐
          │ game_match_candidates       │
          │ game_source_mapping         │
          │ совпадения требуют проверки│
          └─────────────────────────────┘

┌─────────────────┐   ┌────────────────┐   ┌───────────────────┐
│ twitch_games    │   │ youtube_search_ │   │ twitch_streamers  │
│ игра × месяц    │   │ rows: видео     │   │ стример           │
└─────────────────┘   └────────────────┘   └───────────────────┘

┌─────────────────┐   ┌────────────────────┐
│ twitch_global   │   │ steam_game_metadata│
│ платформа × мес.│   │ описание и теги    │
└─────────────────┘   └────────────────────┘

┌─────────────────┐   ┌────────────────────┐
```

Связи Steam Monthly Players с каталогом Steam и рекомендаций с каталогом набора рекомендаций создаются по ID. Межплатформенные связи по названию хранятся отдельно как кандидаты.

## Физическая организация

### Исходные данные: `raw/`

Ноутбук 2.2 сохраняет исходные файлы:

- Kaggle-наборы Steam, RAWG и Twitch;
- результаты поиска и статистики YouTube API;
- тексты статей Habr;
- XML-ответ Wikidata.

Исходные данные служат входом для 2.3 и не должны заменяться подготовленными результатами.

### Подготовленные данные: `processed/`

Ноутбук 2.3 записывает табличные наборы в Parquet:

```text
processed/
├── games/
│   ├── steam_games.parquet
│   ├── rawg_games.parquet
│   ├── wikidata_games.parquet
│   ├── game_match_candidates.parquet
│   └── game_source_mapping.parquet
├── recommendations/
│   ├── steam_recommendation_games.parquet
│   ├── steam_recommendations.parquet
│   ├── steam_users.parquet
│   └── steam_game_metadata.parquet
├── players/
│   └── steam_monthly_players.parquet
├── twitch/
│   ├── twitch_games.parquet
│   ├── twitch_global.parquet
│   └── twitch_streamers.parquet
├── youtube/
│   └── youtube_search_rows.parquet
└── text/
    └── habr_articles.parquet
```

Текстовые признаки сохраняются отдельно в `processed/text/`: для Habr и YouTube создаются TF-IDF-матрица, словарь признаков и список ID документов.

### Аналитическое хранилище: DuckDB

Ноутбук 2.3 загружает подготовленные таблицы в `warehouse/games.duckdb`. Таблицы DuckDB имеют те же имена, что и соответствующие подготовленные наборы.

Текущие представления:

- `v_steam_monthly_players` — месячные показатели Steam с названием игры из каталога Steam;
- `v_steam_recommendations` — рекомендации с названием игры из каталога Steam Recommendations.

В хранилище также загружаются `game_match_candidates` и `game_source_mapping`.

## Правила интеграции

- Steam AppID, RAWG `id` и Wikidata URI — идентификаторы разных систем.
- Steam Monthly Players связывается с каталогом Steam по AppID.
- Рекомендации связываются с каталогом набора рекомендаций по `app_id`.
- RAWG, Wikidata и Twitch сопоставляются со Steam по нормализованным названиям.
- Совпадение названия не подтверждает, что записи относятся к одной игре. Статус уникального совпадения остаётся непроверенным до ручной проверки.
- `game_name` YouTube — запрос поиска, а не подтверждённая связь видео с игрой.
- Данные разной детализации не объединяются в одну широкую таблицу, чтобы не размножать строки и не смешивать показатели.

## Создаваемые отчёты

Ноутбук 2.2 сохраняет реестр источников в `docs/data_sources_registry.csv`.

Ноутбук 2.3 создаёт:

- `docs/data_quality/raw_inventory_2_3.csv`;
- `docs/data_quality/column_quality_2_3.csv`;
- `docs/data_quality/table_summary_2_3.csv`;

- `docs/data_quality/processing_times_2_3.csv`.

## Перенос и повторный запуск

Пути в ноутбуках строятся относительно каталога проекта. Для повторного получения результатов на другом компьютере:

1. получить репозиторий;
2. настроить доступ к Kaggle;
3. создать локальный `.env` с `YOUTUBE_API_KEY`;
4. запустить 2.2;
5. запустить 2.3 из чистого ядра.

Каталоги `raw/`, `processed/`, `warehouse/` и `.env` исключены из Git. Поэтому `git pull` обновляет код и документацию, а локальные данные создаются запуском ноутбуков.

## Ограничения

- YouTube анализируется по текстовым метаданным, без обработки аудио или видеоряда.
- В Wikidata строка результата SPARQL не обязательно соответствует уникальной игре.
- Две статьи Habr подходят для демонстрации NLP, но не для репрезентативных выводов.
- Повторный сбор внешних данных зависит от доступности источников, API-квот и версий наборов.
