# Реестр источников данных

## 1. Назначение

В документе приведён перечень источников, используемых для исследования взаимосвязи характеристик видеоигр и показателей интереса игровой аудитории.

Источники сгруппированы по типу данных и аналитическому назначению.

### Статусы источников

- **Реализован** — получение данных реализовано в текущем сценарии сбора или файл уже присутствует в проекте.
- **Дополнительный** — данные присутствуют в проекте, но не входят в основной перечень источников текущего сценария 2.2.
- **Подготовка в 2.3** — источник выбран для обработки, но его профилирование и преобразование ещё не завершены.
- **Планируется** — источник выбран, но получение данных ещё не реализовано.

Steam Reviews включается в обработку 2.3 как основной источник пользовательских текстов. Перед обработкой необходимо проверить фактическую схему файла, объём, наличие текстового поля, идентификаторов игр и оценок.

Для ресурсоёмких операций допускается использовать детерминированную выборку отзывов с фиксированным random seed.

Основные характеристики Steam Games:

- числовые: `recommendations`, `positive`, `negative`, `price`, `peak_ccu`, `average_playtime_forever`, `average_playtime_2weeks`, `metacritic_score`;
- категориальные: `genres`, `categories`, `tags`, `developers`, `publishers`, `windows`, `mac`, `linux`;
- временные: `release_date`.

Ключевой идентификатор Steam — `AppID` / `appid`.

Для Steam Reviews названия полей и характеристики фиксируются по фактической схеме файла в ходе профилирования 2.3.

### 2.2. RAWG

| Набор данных | Путь | Содержание | Статус |
|---|---|---|---|
| RAWG Games Dataset | `raw/rawg/` | Каталог игр, жанры, платформы, рейтинги, теги, даты выхода | Реализован |

В проекте представлены CSV, Parquet и JSONL-представления одного набора данных. Разные форматы одного источника не рассматриваются как независимые наборы данных.

Основные характеристики:

- числовые: `rating`, `ratings_count`, `reviews_count`, `metacritic`, `playtime`, `suggestions_count`;
- категориальные: `genres`, `platforms`, `stores`, `developers`, `publishers`, `esrb_rating`;
- временные: `released`, `updated`.

Идентификатор RAWG — `id`. Сопоставление с другими платформами выполняется отдельно, поскольку идентификаторы разных платформ не являются взаимозаменяемыми.

### 2.3. Twitch

| Набор данных | Путь | Содержание | Статус |
|---|---|---|---|
| Evolution of Top Games on Twitch | `raw/twitch/evolution/` | Динамика просмотров и трансляций по играм | Реализован |
| Top 1000 Twitch Streamers | `raw/twitch/streamers/` | Характеристики популярных стримеров | Реализован |

Основные характеристики Twitch Evolution:

- числовые: `Hours_watched`, `Hours_streamed`, `Peak_viewers`, `Peak_channels`, `Streamers`, `Avg_viewers`, `Avg_channels`, `Avg_viewer_ratio`;
- категориальные: `Game`, месяц, год;
- временные: `Month`, `Year`.

Характеристики Twitch Streamers:

- категориальные: `NAME`, `LANGUAGE`, `TYPE`, `MOST_STREAMED_GAME`, `2ND_MOST_STREAMED_GAME`, `MOST_ACTIVE_DAY`;
- числовые: `FOLLOWERS_GAINED_PER_STREAM`, `AVG_VIEWERS_PER_STREAM`, `AVG_GAMES_PER_STREAM`, `TOTAL_TIME_STREAMED`, `TOTAL_FOLLOWERS`, `TOTAL_VIEWS`, `TOTAL_GAMES_STREAMED`, `ACTIVE_DAYS_PER_WEEK`;
- временные и календарные: `MOST_ACTIVE_DAY`, если он используется как календарная характеристика.

`TYPE` описывает тип стримера в исходном наборе. Его нельзя автоматически интерпретировать как партнёрский статус или возрастное ограничение.

Twitch Evolution и Twitch Streamers описывают разные объекты исследования: игровую активность и характеристики отдельных стримеров.

| Набор данных | Путь | Содержание | Статус |
|---|---|---|---|

Epic Games Store рассматривается как дополнительный источник характеристик игр. Перед включением в итоговую интегрированную таблицу проверяются структура, полнота и возможность сопоставления с другими платформами.

Основные характеристики:

- числовые: цена, оценки и числовые системные характеристики после преобразования;
- категориальные: жанры, разработчик, издатель, платформа, функции;
- временные: дата релиза.

Идентификатор игры в Epic требует отдельного исследования. Для сопоставления с другими платформами может использоваться нормализованное название с дополнительной проверкой.

## 3. Источники с API и JSON

### 3.1. YouTube Data API v3

Документация: https://developers.google.com/youtube/data/reference/rest/v3/search/list?hl=ru

YouTube Data API v3 используется для получения метаданных и статистики видеороликов, связанных с наиболее популярными играми Steam.

В рамках этапа 2.2 получено 300 видеозаписей.

Фактические поля подготовленного набора:

- `game_name`;
- `video_id`;
- `title`;
- `description`;
- `channel_title`;
- `published_at`;
- `views`;
- `likes`;
- `comments`.

В качестве объектов поиска используются 30 наиболее популярных игр Steam, отобранных по полю `recommendations`.

Ограничения:

- поисковая выдача не гарантирует, что каждый ролик непосредственно посвящён игре;
- название игры может совпадать с другими сущностями;
- `video_id` является идентификатором видеоролика, а не игры;
- `game_name` отражает поисковый запрос и не гарантирует подтверждённую связь с игрой;
- статистика видео отражает накопленные значения на дату сбора;
- отдельные показатели статистики могут отсутствовать;
- API key хранится локально в `.env`.

Статус: реализован.

## 4. Неструктурированные данные

### 4.1. Habr

Используются публикации, посвящённые игровой индустрии, платформам и распределению внимания аудитории.

Материалы:

1. https://habr.com/ru/articles/995396/
2. https://habr.com/ru/articles/990554/

Извлекаемые данные:

- заголовок;
- дата публикации;
- автор, если доступен;
- текст публикации;
- URL;
- тематические ключевые слова.

Тексты используются для демонстрации обработки неструктурированных данных: очистки, нормализации, токенизации и TF-IDF-векторизации.

Две статьи не являются репрезентативной выборкой всей игровой индустрии. Их анализ рассматривается как демонстрация технологического этапа обработки текстовых данных и контекстный материал.

Статус: реализован.

### 4.2. Steam Reviews

Источник: `raw/steam/reviews/dataset.csv`.

Steam Reviews используется как основной массив пользовательских текстов для исследования пользовательского восприятия игр.

Планируемые операции:

- проверка фактической структуры и типов данных;
- анализ пропусков и дубликатов;
- проверка наличия текстов отзывов и оценок;
- формирование воспроизводимой выборки при необходимости;
- очистка и нормализация текста;
- токенизация;
- лемматизация или стемминг при обоснованной необходимости;
- TF-IDF-векторизация;
- сопоставление отзывов с играми по идентификаторам источника, если такие идентификаторы присутствуют.

Фактические названия полей и доступные характеристики фиксируются после профилирования в 2.3.

Статус: выбран для обработки в 2.3.

### 4.3. YouTube-тексты

Поля `title` и `description` из YouTube Data API v3 могут использоваться как дополнительные текстовые признаки.

Тексты видеороликов не рассматриваются как пользовательские отзывы и не смешиваются с корпусом Steam Reviews без явного указания типа документа.

Статус: реализован.

## 5. Иерархические XML-данные

### 5.1. Wikidata Query Service

Источник: https://query.wikidata.org/sparql

Документация: https://www.mediawiki.org/wiki/Wikidata_Query_Service/User_Manual

Wikidata Query Service используется для получения сведений о видеоиграх посредством SPARQL-запросов с сохранением результата в XML-формате.

Исходный файл:

`raw/xml/wikidata/wikidata_video_games.xml`

Выгрузка содержит сведения о видеоиграх и их характеристиках:

- название игры;
- идентификатор Wikidata;
- жанры;
- платформы;
- разработчики;
- издатели;
- режимы игры;
- рейтинги ESRB;
- рейтинги PEGI;
- дата выхода;
- минимальное количество игроков;
- максимальное количество игроков.

Основные свойства Wikidata:

| Характеристика | Свойство |
|---|---|
| Тип объекта — видеоигра | `P31` |
| Жанр | `P136` |
| Разработчик | `P178` |
| Издатель | `P123` |
| Платформа | `P400` |
| Дата выхода | `P577` |
| Режим игры | `P404` |
| ESRB | `P852` |
| PEGI | `P908` |
| Минимальное количество игроков | `P1872` |
| Максимальное количество игроков | `P1873` |

Категориальные характеристики: жанры, платформы, разработчики, издатели, режимы игры и возрастные рейтинги.

Числовые характеристики: год выхода (производный атрибут), минимальное и максимальное количество игроков.

Ограничения:

- данные Wikidata могут быть неполными;
- наличие свойства у игры не гарантируется;
- значения могут различаться по полноте и качеству;
- сведения внесены разными участниками и требуют проверки;
- идентификатор Wikidata не совпадает с идентификаторами Steam и RAWG;
- результат SPARQL-запроса является выборкой из базы знаний, а не полным дампом всех видеоигр.

XML-файл сохраняется в `raw/` без изменения содержания. Разбор, очистка и преобразование выполняются на этапе 2.3.

Статус: выбран для реализации в 2.2; после успешной загрузки и проверки XML-структуры переводится в статус «Реализован».

## 6. Исключённые и неиспользуемые источники

В текущей реализации не используются:

- Steam API;
- RAWG API;
- набор Steam Player Data 2012–2021, ранее исключённый из отбора;
- Росстат;
- дополнительные источники, которые не прошли проверку доступности, качества или соответствия предмету исследования.

Старые наборы данных, присутствующие в `raw/`, не считаются автоматически частью текущего сценария 2.2. Их статус определяется отдельно.

## 7. Соответствие требованиям методички

| Требование | Источник | Статус |
|---|---|---|
| Не менее одного реляционного набора | Steam, RAWG, Twitch | Выполняется |
| Не менее одного иерархического XML-набора | Wikidata Query Service, XML-ответ SPARQL | Выполняется после успешной загрузки и проверки XML |
| Не менее одного API с JSON | YouTube Data API v3 | Выполняется |
| Неструктурированные данные | Steam Reviews, Habr, YouTube-тексты | Выполняется после проверки текстовых полей и подготовки |

Для каждого набора данных отдельно проверяется наличие не менее трёх категориальных и трёх числовых характеристик. Если источник не содержит требуемых характеристик или они имеют слишком большое число пропусков, это фиксируется как ограничение, а не компенсируется искусственным созданием показателей.

Наличие источника в реестре само по себе не означает, что все его поля пригодны для анализа. Окончательное соответствие требованиям подтверждается профилированием в ноутбуке 2.3.
