# Исследование данных игровых платформ

Курсовой проект по дисциплине «Технологии обработки больших данных».

**Тема:** «Исследование данных игровых платформ для выявления паттернов популярности и предпочтений игроков».

## Цель исследования

Выявить статистические закономерности и взаимосвязи между характеристиками видеоигр и показателями интереса игровой аудитории на основе открытых данных игровых и медиаплатформ.

В исследовании рассматриваются:

- характеристики видеоигр: жанры, теги, стоимость, дата выхода, платформы, разработчики и издатели;
- пользовательская активность: рекомендации, отзывы, количество игроков и продолжительность игрового времени;
- медиапопулярность: просмотры игровых трансляций и видеороликов;
- пользовательские оценки и характеристики игр из нескольких источников.

Машинное обучение в проекте не используется без отдельного обоснования. Основной методологической базой являются методы математической статистики, сравнительного анализа, анализа временных рядов и визуализации.

## Источники данных

В проекте рассматриваются следующие группы источников:

- **Steam** — характеристики игр, пользовательские рекомендации, отзывы и активность игроков.
- **RAWG** — каталог видеоигр, жанры, теги, платформы и пользовательские оценки.
- **Epic Games Store** — характеристики игр, стоимость, жанры, издатели и разработчики.
- **Twitch** — показатели просмотров и трансляций по играм.
- **YouTube Data API v3** — метаданные и статистика видеороликов, связанных с наиболее популярными играми.
- **Habr** — текстовые публикации об игровой индустрии и популярности видеоигр.
- **Росстат** — потенциальный источник официальных статистических данных; подключение отложено до получения и проверки файлов.

Steam, RAWG, Epic Games Store и Twitch представлены локально собранными наборами данных. Для получения YouTube используется YouTube Data API v3. Steam API и RAWG API в текущей реализации не используются.

Подробный реестр источников и их статус приведён в [docs/DATASOURCES.md](docs/DATASOURCES.md).

## Архитектура данных

Проект использует трёхуровневую схему:

1. `raw/` — исходные данные, сохранённые без изменения содержания.
2. `processed/` — очищенные и преобразованные наборы данных в Parquet.
3. `warehouse/` — аналитическое хранилище DuckDB для интеграции и последующего анализа.

Основной формат хранения подготовленных табличных данных — Parquet. DuckDB используется для чтения, профилирования, преобразования и объединения больших наборов данных без необходимости загружать их целиком в оперативную память.

Подробная схема описана в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Критерий отбора игр для YouTube

Для сбора видеоматериалов формируется выборка из 30 наиболее популярных игр Steam.

Основной критерий ранжирования — количество пользовательских рекомендаций Steam (`recommendations`). Выборка строится по убыванию этого показателя. Для каждой игры выполняется поиск видеороликов через YouTube Data API v3.

Выборка используется для исследования связи между популярностью игры на игровой платформе и вниманием аудитории к видеоконтенту. Она не является случайной выборкой всех существующих игр.

## Безопасность

Ключ YouTube Data API хранится локально в файле `.env` и не должен попадать в Git.

Файл `.env` включён в `.gitignore`. Для воспроизведения сбора данных необходимо самостоятельно создать API key в Google Cloud Console и указать его в локальном `.env`.
