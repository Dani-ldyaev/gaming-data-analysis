# Исследование данных игровых платформ

Курсовой проект по дисциплине «Технологии обработки больших данных».

**Тема:** «Исследование данных игровых платформ для выявления паттернов популярности и предпочтений игроков».

## Цель исследования

Выявить статистические закономерности и взаимосвязи между характеристиками видеоигр и показателями интереса игровой аудитории на основе открытых данных игровых и медиаплатформ.

В исследовании рассматриваются:

- характеристики видеоигр: жанры, теги, стоимость, дата выхода, платформы, разработчики и издатели;
- пользовательская активность: рекомендации, отзывы, количество игроков и продолжительность игрового времени;
- медиапопулярность: просмотры игровых трансляций и видеороликов;
- пользовательские оценки и характеристики игр из нескольких источников;
- дополнительные характеристики видеоигр из открытой базы знаний Wikidata.

Машинное обучение для построения предсказательных моделей в проекте не используется. Основной методологической базой являются методы математической статистики, сравнительного анализа, анализа временных рядов и визуализации. Для обработки текстов допускается применение методов токенизации и TF-IDF-векторизации.

Работа выполняется в соответствии с CRISP-DM и методическими указаниями к курсовому проекту.

## Источники данных

В проекте используются следующие группы источников:

- **Steam** — характеристики игр, пользовательские рекомендации, отзывы и активность игроков.
- **RAWG** — каталог видеоигр, жанры, теги, платформы и пользовательские оценки.
- **Epic Games Store** — дополнительные характеристики игр, стоимость, жанры, издатели и разработчики.
- **Twitch** — показатели просмотров и трансляций по играм, а также характеристики популярных стримеров.
- **YouTube Data API v3** — метаданные и статистика видеороликов, связанных с наиболее популярными играми.
- **Habr** — текстовые публикации об игровой индустрии и популярности видеоигр.
- **Wikidata Query Service** — дополнительные сведения о видеоиграх, получаемые в иерархическом XML-формате.

Основные источники Steam, RAWG и Twitch представлены локально собранными наборами данных. YouTube Data API v3 используется для получения JSON-ответов. Wikidata Query Service используется для получения XML-ответов на SPARQL-запросы.

Steam API и RAWG API в текущей реализации не используются.

Подробный реестр источников, характеристики и статусы представлены в [docs/DATASOURCES.md](docs/DATASOURCES.md).

## Критерий отбора игр для YouTube

Для сбора видеоматериалов формируется выборка из 30 наиболее популярных игр Steam.

Основной критерий ранжирования — количество пользовательских рекомендаций Steam (`recommendations`). Выборка строится по убыванию этого показателя. Для каждой игры выполняется поиск видеороликов через YouTube Data API v3.

Выборка используется для исследования связи между популярностью игры на игровой платформе и вниманием аудитории к видеоконтенту. Она не является случайной выборкой всех существующих игр.

## Подготовка текстовых данных

Для текстового анализа предусмотрены:

- пользовательские отзывы Steam;
- описания видеороликов YouTube;
- публикации Habr.

Steam Reviews используется как основной массив пользовательских текстов. Для ресурсоёмких операций допускается формирование воспроизводимой выборки отзывов.

Материалы Habr и описания YouTube рассматриваются как дополнительные текстовые источники. Небольшое количество статей Habr не позволяет считать их репрезентативной выборкой всей игровой индустрии.

Для обработки текстов применяются очистка, нормализация, токенизация и TF-IDF-векторизация. Эти операции используются для описательного анализа и не являются построением предсказательной ML-модели.

## Архитектура данных

Проект использует трёхуровневую схему:

1. `raw/` — исходные данные, сохранённые без изменения содержания.
2. `processed/` — очищенные и преобразованные наборы данных, преимущественно в формате Parquet.
3. `warehouse/` — аналитическое хранилище DuckDB для интеграции и последующего анализа.

Основной формат хранения подготовленных табличных данных — Parquet. DuckDB используется для чтения, профилирования, преобразования и объединения больших наборов данных без необходимости загружать их целиком в оперативную память.

Для объединения данных из разных платформ формируется таблица сопоставления игр. Идентификаторы Steam, RAWG, Wikidata и других источников не считаются взаимозаменяемыми. Совпадения по названиям требуют проверки.

Подробная схема описана в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Безопасность

Ключ YouTube Data API хранится локально в файле `.env` и не должен попадать в Git.

Файл `.env` включён в `.gitignore`. Для воспроизведения сбора данных необходимо самостоятельно создать API key в Google Cloud Console и указать его в локальном `.env`.

## Статус проекта

Проект находится на этапе формирования информационной базы и подготовки данных.

В рамках этапа 2.2 реализованы:

- загрузка шести Kaggle-наборов через KaggleHub;
- получение видеоматериалов через YouTube Data API v3;
- извлечение двух текстовых публикаций Habr;
- получение XML-данных о видеоиграх через Wikidata Query Service.

Дополнительно в проекте имеются ранее загруженные наборы Epic Games Store и Steam Reviews, которые рассматриваются при формировании аналитической базы и подготовке данных.

На этапе 2.3 выполняются инвентаризация, профилирование, очистка, преобразование, текстовая обработка, сопоставление источников и формирование подготовленных наборов данных.

Фактическое наличие файлов и итоговые показатели качества фиксируются в ноутбуках и отчётах `docs/data_quality/`.
