# Исследование данных игровых платформ

Курсовой проект по дисциплине «Технологии обработки больших данных».

**Тема:** исследование связи характеристик видеоигр и показателей интереса аудитории на игровых и медиаплатформах.

## Цель

Исследовать статистические связи между характеристиками игр и показателями интереса аудитории по данным Steam, RAWG, Twitch, YouTube и Wikidata. Статьи Habr используются как контекстный материал для NLP и сопоставления опубликованных количественных утверждений с данными Steam.

Анализ выявляет статистические ассоциации. Он не доказывает причинное влияние характеристик игры на интерес аудитории.

## Этапы проекта

| Этап | Содержание |
|---|---|
| 2.2 | Сбор открытых источников и первичная инвентаризация |
| 2.3 | Подготовка данных, профилирование, NLP и организация Parquet/DuckDB |
| 2.4 | Статистический анализ, модели и описательное сопоставление источников |
| 2.5 | Сравнение времени загрузки локальных файлов, подготовки, объединения и анализа |
| 2.6 | Интерактивное представление результатов |

## Структура

- `notebooks/2_2.ipynb`–`notebooks/2_6.ipynb` — этапы проекта.
- `docs/DATASOURCES.md` — источники и ограничения.
- `docs/DATA_DICTIONARY.md` — подготовленные таблицы и аналитические результаты.
- `docs/ARCHITECTURE.md` — слои данных, связи и хранилище.
- `docs/data_sources_registry.csv` — реестр источников из 2.2.
- `docs/data_quality/` — отчёты о качестве и результаты анализа.
- `requirements.txt` — Python-зависимости.

Каталоги `raw/`, `processed/`, `warehouse/` и `.env` не хранятся в Git. Их содержимое создаётся повторным запуском ноутбуков.

## Используемые источники

Текущий процесс использует игровые каталоги Steam и RAWG, Steam Recommendations, Steam Monthly Players, Twitch, YouTube Data API v3, две статьи Habr и XML-ответ Wikidata.

Steam Reviews и Epic Games Store в текущие ноутбуки не входят. Habr используется только как небольшой иллюстративный корпус. YouTube-поисковый запрос не доказывает, что каждое найденное видео посвящено соответствующей игре.

## Запуск

1. Установить зависимости из `requirements.txt`.
2. Настроить Kaggle API на текущем устройстве.
3. Создать локальный `.env` в корне проекта с `YOUTUBE_API_KEY`.
4. Выполнить `notebooks/2_2.ipynb`.
5. Выполнить `notebooks/2_3.ipynb` из чистого ядра.
6. Затем последовательно выполнить `2_4`, `2_5` и `2_6`.

Пути задаются относительно корня проекта. Получение данных зависит от доступности внешних источников, API-квоты и версий наборов.

## Основные ограничения

- Совпадение названий между Steam, RAWG, Twitch и Wikidata — непроверенный кандидат, а не подтверждённая идентичность игры.
- YouTube связан с поисковым запросом; содержание видео автоматически не проверялось.
- Twitch и Steam Monthly Players покрывают разные временные интервалы.
- Две статьи Habr не репрезентируют игровую индустрию.
- Время сетевого скачивания источников в 2.2 не записывалось; в 2.5 сравнивается локальное чтение файлов.
