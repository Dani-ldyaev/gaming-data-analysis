# Исследование данных игровых платформ

Курсовой проект по дисциплине «Технологии обработки больших данных».

**Тема:** исследование связи характеристик видеоигр и показателей интереса аудитории на игровых и медиаплатформах.

## Цель

Подготовить и исследовать данные Steam, RAWG, Twitch, YouTube, Habr и Wikidata, чтобы выявить статистические связи между характеристиками игр и показателями их популярности.

## Этапы проекта

| Этап | Содержание |
|---|---|
| 2.2 | Получение источников данных и первичная инвентаризация |
| 2.3 | Профилирование, очистка, преобразование, NLP и организация данных |
| 2.4 | Анализ данных и проверка гипотез |
| 2.5 | Сравнение методов и измерение времени обработки |
| 2.6 | Представление результатов проекта |

Этапы выполняются по порядку. Содержание 2.4–2.6 описывается по мере разработки соответствующих ноутбуков.

## Структура проекта

- `notebooks/2_2.ipynb`–`notebooks/2_6.ipynb` — этапы проекта.
- `docs/DATASOURCES.md` — используемые источники и файлы.
- `docs/DATA_DICTIONARY.md` — описание подготовленных таблиц.
- `docs/ARCHITECTURE.md` — процесс обработки и организация хранилища.
- `docs/data_sources_registry.csv` — реестр источников, создаваемый 2.2.
- `docs/data_quality/*_2_3.csv` — отчёты, создаваемые 2.3.
- `requirements.txt` — основные Python-зависимости.

Каталоги `raw/`, `processed/`, `warehouse/` и локальный файл `.env` не хранятся в Git. Данные можно получить и подготовить повторным запуском 2.2 и 2.3.

## Используемые источники

В текущем процессе используются каталоги игр Steam и RAWG, рекомендации и метаданные Steam, Steam Monthly Players, данные Twitch, YouTube Data API v3, две статьи Habr и результаты запроса Wikidata.

Steam Reviews и Epic Games Store в актуальные ноутбуки 2.2 и 2.3 не входят.

Подробности приведены в [реестре источников](docs/DATASOURCES.md), описание подготовленных полей — в [словаре данных](docs/DATA_DICTIONARY.md).

## Запуск

1. Клонировать репозиторий и установить зависимости из `requirements.txt`.
2. Настроить доступ к наборам Kaggle, используемым в 2.2.
3. Создать в корне проекта локальный `.env` с переменной `YOUTUBE_API_KEY`.
4. Запустить `notebooks/2_2.ipynb` целиком.
5. Затем запустить `notebooks/2_3.ipynb` целиком из чистого ядра.

Ноутбуки используют пути проекта, а не абсолютные пути конкретного компьютера. Повторный запуск 2.2 обращается к внешним источникам и API; результаты зависят от доступности источников, API-квоты и версии наборов.

## Ограничения

Совпадение названий игр между платформами формирует кандидатов на связь, но не подтверждает идентичность игры. Название игры в YouTube является поисковым запросом. NLP YouTube выполняется по заголовкам и описаниям, а не по видео или аудио. Две статьи Habr демонстрируют обработку текста, но не дают репрезентативной выборки отрасли.
