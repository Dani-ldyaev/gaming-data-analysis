## 2.2. Подбор и анализ источников данных

Для исследования используются открытые наборы данных и API, описывающие характеристики видеоигр, пользовательские отзывы и популярность игр. Источники позволяют анализировать состояние игрового рынка и изучать возможные факторы влияния на популярность игр.

### 1. Каталог источников данных

| № | Источник | Формат | Тип данных | Назначение |
|---|---|---|---|---|
| 1 | [Steam Games Dataset](https://www.kaggle.com/datasets/fronkongames/steam-games-dataset) | JSON (`games.json`) | Структурированные данные | Анализ характеристик игр и их популярности |
| 2 | [BoardGameGeek XML API 2](https://boardgamegeek.com/wiki/page/BGG_XML_API2) | XML | Иерархические данные | Изучение структуры XML и получение дополнительных характеристик игр |
| 3 | [RAWG API](https://api.rawg.io/docs/) | JSON | Структурированные данные через API | Получение жанров, платформ, оценок и дат выхода игр |
| 4 | [Steam User Reviews API](https://partner.steamgames.com/doc/webapi/IUserReviewsService) | JSON с текстовыми отзывами | Неструктурированный текст | Анализ пользовательских отзывов и оценок |
| 5 | [Twitch Helix API](https://dev.twitch.tv/docs/api/reference) | JSON | Структурированные данные через API | Оценка популярности игр по активности зрителей и стримеров |

### 2. Характеристики источников

#### 2.1. Steam Games Dataset

**Объект исследования:** видеоигры, представленные в Steam.

- **Категориальные признаки:** жанр (`genres`), разработчик (`developers`), издатель (`publishers`), категории игры (`categories`).
- **Числовые признаки:** цена (`price`), количество положительных отзывов (`positive`), количество отрицательных отзывов (`negative`), среднее время игры (`average_playtime`), пиковое количество одновременно играющих пользователей (`peak_ccu`).
- **Временные признаки:** дата выхода игры (`release_date`).
- **Идентификатор:** `appid`.

Источник используется для анализа связи характеристик игр с пользовательской активностью, количеством отзывов и популярностью.

Файл `games.json` загружается в табличное хранилище DuckDB для последующего анализа.

#### 2.2. BoardGameGeek XML API 2

**Объект исследования:** игровые объекты, доступные через API, при наличии подходящих записей категории `videogame`.

- **Категориальные признаки:** название, издатель, разработчик или автор, категории и механики — в зависимости от доступности в ответе.
- **Числовые признаки:** год выпуска, рейтинг и количество оценок — при наличии соответствующих полей.
- **Временные признаки:** год выпуска и дата получения данных.
- **Идентификатор:** ID объекта BoardGameGeek.

Источник предназначен для работы с иерархическими XML-данными и изучения вложенной структуры объектов.

Перед включением в итоговый набор данных необходимо проверить доступность видеоигр и наличие минимум трёх категориальных и трёх числовых характеристик. Если условия не выполняются, источник необходимо заменить другим XML-источником, соответствующим требованиям задания.

#### 2.3. RAWG API

**Объект исследования:** видеоигры из каталога RAWG.

- **Категориальные признаки:** жанры (`genres`), платформы (`platforms`), возрастной рейтинг (`esrb_rating`), разработчики (`developers`).
- **Числовые признаки:** пользовательский рейтинг (`rating`), количество оценок (`ratings_count`), оценка Metacritic (`metacritic`), среднее время игры (`playtime`) — если поле доступно.
- **Временные признаки:** дата выхода (`released`), дата обновления записи (`updated`) — если доступна.
- **Идентификатор:** `id`.

Источник используется для расширения каталога игр и сравнения характеристик, жанров, платформ и пользовательских оценок.

Для получения данных требуется API-ключ. Фактический состав полей проверяется по ответам API.

#### 2.4. Steam User Reviews API

**Объект исследования:** пользовательские отзывы о видеоиграх.

- **Категориальные признаки:** язык (`language`), тип отзыва (`review_type`), тип покупки (`purchase_type`).
- **Числовые признаки:** количество голосов за полезность (`votes_up`), количество голосов за смешной отзыв (`votes_funny`), взвешенная оценка полезности (`weighted_vote_score`), время игры к моменту отзыва (`playtime_at_review`) — если доступно.
- **Временные признаки:** время публикации (`timestamp_created`), время обновления (`timestamp_updated`).
- **Идентификаторы:** ID игры и ID отзыва.
- **Текстовые данные:** содержание отзыва (`review`).

Источник позволяет изучать распределение положительных и отрицательных отзывов, популярные темы обсуждений и динамику пользовательских оценок.

Текст отзывов рассматривается как неструктурированные данные. Для анализа можно использовать частотный анализ слов, группировку отзывов по признакам и сравнение результатов между жанрами и играми.

#### 2.5. Twitch Helix API

**Объект исследования:** трансляции видеоигр и активность их аудитории.

- **Категориальные признаки:** название игры (`game_name`), язык трансляции (`language`), тип трансляции (`type`), имя стримера (`user_name`).
- **Числовые признаки:** количество зрителей (`viewer_count`), количество трансляций за период, количество уникальных стримеров за период.
- **Временные признаки:** время начала трансляции (`started_at`), дата сбора данных.
- **Идентификаторы:** `game_id`, `user_id`.

Источник используется для оценки внешней популярности игр. Количество трансляций и уникальных стримеров рассчитывается на основе сохранённых данных за выбранный период.

Для работы с API требуется настроить авторизацию. Для анализа динамики необходимо регулярно сохранять снимки данных.

### 3. Связь источников с задачами исследования

| Задача исследования | Источники | Основные показатели |
|---|---|---|
| Анализ характеристик игрового рынка | Steam Games Dataset, RAWG API | Жанры, платформы, цены, даты выхода |
| Анализ пользовательских оценок | Steam Games Dataset, RAWG API, Steam Reviews API | Рейтинги, положительные и отрицательные отзывы, количество оценок |
| Анализ пользовательской активности | Steam Games Dataset, Steam Reviews API | Пиковое число игроков, время игры, количество отзывов |
| Анализ популярности игр на стриминговых платформах | Twitch Helix API | Количество зрителей, трансляций и стримеров |
| Изучение иерархических данных | BoardGameGeek XML API 2 | Вложенные элементы XML и доступные характеристики объектов |
| Анализ изменений во времени | Steam Reviews API, Twitch Helix API, RAWG API | Даты публикации отзывов, снимки активности, даты обновления данных |

### 4. Интеграция данных

Для объединения источников предусматривается единый справочник игр, содержащий идентификаторы из разных платформ и соответствия между ними.

Основным ключом для данных Steam является `appid`. Для RAWG используется `id`, для Twitch — `game_id`, для BoardGameGeek — ID соответствующего объекта.

Если идентификаторы разных платформ не совпадают, используется отдельная таблица соответствий. Объединение только по названию игры применяется с дополнительной проверкой, поскольку названия могут различаться или относиться к разным изданиям.

### 5. Ограничения и проверка качества

При подготовке данных необходимо:

- проверить наличие обязательных категориальных и числовых признаков в каждом источнике;
- проверить пропуски, дубликаты, типы данных и корректность дат;
- привести названия и идентификаторы полей к единому формату;
- зафиксировать дату выгрузки данных;
- учитывать ограничения API, доступность полей и условия использования источников;
- не считать расчётные показатели исходными полями API;
- документировать преобразования при загрузке JSON и XML в табличное хранилище.

Таким образом, выбранные источники позволяют исследовать характеристики видеоигр, пользовательские оценки, активность игроков и внешнюю популярность игр, а также охватывают реляционные, иерархические, API- и текстовые данные.
